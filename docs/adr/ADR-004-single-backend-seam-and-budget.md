# ADR-004: Every model call goes through one Backend seam that counts, caches, retries and stops

- **Status:** Proposed (revised 2026-10-03 after G3 rounds 1 and 2 and the pre-flight reviews)
- **Date:** 2026-10-03
- **Requirement(s):** R17, R18, R19, R20, R22, R24

## Context

GEPA's `max_metric_calls` does not count reflection calls, and each call here is a `claude -p` process on the user's Max plan. Calls must be countable, capped, resumable and safe, and tests must never reach a real model. Probes in the G3 round 1 vote showed what GEPA 0.1.4 does with exceptions raised inside the search: with `raise_on_exception=True` (the default) a `BudgetExhausted` escapes `optimize_anything` and the result is lost; with `False` the error is scored 0.0 and the search keeps going, so a dead backend burns the whole budget and exit 3 never happens.

## Decision

1. **Protocol.** `Backend.complete(Call) -> Reply`. `Call` carries `role, model, user, system, json_schema, sample`; all of them are part of the cache key. The wire formats of the messages are ADR-008. `sample` exists so the second seed run (R12) is a different call; reflection calls carry a running index for the same reason (a stalled search would otherwise replay one cached proposal for free until the clock ended). Exceptions: `CallError` is one failed attempt (raised by raw backends), `CallFailed` a call that failed all its attempts, `BackendError` the run-ending condition (three consecutive failed calls, or a failed seed run).
2. **Stack**, outermost first: `Cached(Resilient(Budgeted(ClaudeCli)))`; tests replace `ClaudeCli` only, with `tests/fakes.py`, so the other three layers are exercised.
   - `ClaudeCli` is the only code that builds the `claude -p` command (R18) and the scrubbed environment. User text goes on stdin only. The system prompt is passed as `--system-prompt=<text>` (one argument, so a leading `-` cannot be read as an option) and is limited to `SYSTEM_PROMPT_MAX_BYTES` (100,000, under the 131,072-byte limit of one argument); the runner rejects a longer candidate before running it. The call has a timeout of `min(300 s, clock left)`. The first live call of every process (a resumed run too, whose first live call may be a reflection) aborts with `SessionNotLockedDown` if the session reports plugins, MCP servers or tools.
   - `Budgeted` counts every call that reaches it, starting from the `calls_used` saved in the run folder (so a resume continues the same count), holds the current `limit` and a deadline on the shared monotonic `Clock`, and raises `BudgetExhausted` when either is passed. It is the single enforcement point. The limit starts at `budget - final_costs` (the final steps' share of the R17 reserve): intake, synthesis and the seed runs are paid from it as they happen and the search gets what is left. `raise_limit(budget, deadline)` opens the final steps' share (calls and the last 25 % of the clock) once the search has ended. `--dry` shows the same split up front.
   - `Resilient` retries a failed call twice (each attempt goes through `Budgeted` and counts). A call that still fails raises `CallFailed` and counts toward `MAX_CONSECUTIVE_FAILURES` **per model id**: the third consecutive failed call to the same model raises `BackendError`. A success from another model does not reset the count, so a judge or reflection model that is down while the task model still answers ends the run instead of burning the budget (probe, pre-flight).
   - `Cached` is keyed by the SHA-256 of all `Call` fields, stores only successful replies with the call's `duration_s`, one atomic file per call (ADR-007); a hit does not touch the budget and carries the stored duration in its `Reply`.
3. **Stopping GEPA.** GEPA swallows every exception from the reflection callable (and retries that task once more) and re-raises evaluator exceptions out of `optimize_anything`, so the runner wraps both; the wrappers catch `Exception` only, so Ctrl-C reaches `cli.main` (exit 130). The batch adapter turns a `CallFailed` into a neutral result for that scenario and marks the candidate incomplete; a `CallFailed` while scoring the seed candidate (the original) is recorded as `abort = backend` instead, because the seed's score steers every acceptance and the `--trust-search` comparison and a 0 would lower the bar; any other exception (budget, clock, `BackendError`, `SessionNotLockedDown`, a bug) is recorded in `RunState.abort` and later pairs return neutral results without a call. The reflection wrapper extracts the first fenced block itself and returns only that block (GEPA would keep everything from the first to the last fence), turns an empty reply, a reply without a block, a block containing a GEPA placeholder and a `CallFailed` into `SkipProposal` (GEPA retries once, then skips the iteration; nothing is recorded; the retry is one more paid call), records `BackendError`, `BudgetExhausted`, `SessionNotLockedDown` and any other exception in `RunState.abort`, re-raises (GEPA swallows it) and does not call the model once `abort` is set. A stopper in GEPA's `stop_callbacks` ends the search when `abort` is set, when `calls_left < iter_cost` (`iter_cost = 1 + 2 * (m + 1) + (valset + 1)`, an accepted child; `calls_left = (budget - final) - search_start.used - meter.calls`), or when `search_start.elapsed + meter.seconds + meter.seconds_per_call * iter_cost` reaches the search share of the clock (a one-iteration look-ahead). **The stopper reads a `SearchMeter`, not `Budgeted`:** the meter counts each **distinct** call (by cache key) once, the first time the search issues it, live or from the cache, retries excluded, and sums that first occurrence's duration (live: measured; hit: stored in the cache entry); `search_start` is the `Budgeted.used` and clock reading recorded in `checkpoint.json` when the search first began. A replay issues the same distinct calls in the same order, so the meter and the stopper decide as the original did (probed by cutting a run at every call index for n = 8, 12, 40). Counting every issue instead of every distinct call would charge in-run repeats and leave part of the search share unspent (probe: 24 of 76 calls at n = 8). Reading `Budgeted.used` directly would stop a resumed run before its first iteration and lose every candidate (probes, round 2). `Budgeted` keeps the hard limit on live spending. `raise_on_exception` stays True, so an error in the adapter code itself, which the wrappers do not catch, still escapes `optimize_anything` instead of being scored 0.
4. **After the search.** `RunState.raise_if_aborted()` turns a backend failure into exit 3, a lockdown failure into exit 4 and a bug into exit 1, with the run folder kept. Outside the GEPA adapter (intake, synthesis, the seed runs, finalist runs, contract checks) a `CallFailed` ends the run as `BackendError`, exit 3, because there is no iteration to skip and no score that could stand in for the call. A budget or clock stop continues with the finalists drawn from `RunState.completed` (the seed excluded), run from the final steps' share through the same gates as any other result (R3, R6, R7, R9); a `BudgetExhausted` in the final steps, or the clock running out before a finalist is confirmed, returns the original.
5. **GEPA output.** A custom logger writes GEPA's progress to the run folder and stdout is redirected there while GEPA runs, so stdout holds only the result (R2). `run_dir` is None: no pickled GEPA state is created or loaded.
6. `tests/fakes.py` (`ScriptedBackend`) serves scripted replies for all tests. Prompts and outputs are never passed through a shell.

## Consequences

One place to audit for safety and cost; the reserve is protected because the search can only spend its own share; resume (R22) falls out of the cache because GEPA with the same seed and the same cached replies retraces its steps for free; a failing model ends the run in three failed calls to it instead of burning the budget. One property is deliberately weaker: a call that failed before an interruption is not cached, so a resumed run retries it live and may take a different path afterwards (R22 promises no repeated successful call, not an identical path). The single-turn, no-tools setting means the task model cannot exercise tool use, so prompts that depend on tools are scored on what the model *says* it would do; the report notes this limit. The adapter (wrappers, `RunState`, stopper) is non-trivial code in `runner.py` and needs its own tests against the pinned GEPA.

## Alternatives rejected

- **Count only GEPA metric calls:** misses reflection, intake, synthesis and judge calls.
- **Let `BudgetExhausted` propagate out of GEPA:** loses the result (probe, round 1).
- **`raise_on_exception=False`:** scores errors as 0.0 and keeps searching (probe, round 1).
- **Anthropic API with a key:** violates the no-API-key rule for this machine.
- **`--bare`:** needs an API key and never reads the subscription login.
- **Budget counted above the cache:** would charge cache hits that cost nothing.
